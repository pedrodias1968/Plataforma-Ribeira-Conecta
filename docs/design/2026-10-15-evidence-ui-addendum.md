## 1. Executive Summary

This addendum revises the visual direction document to reflect that **Ribeira Conecta is an authenticated pilot platform, not a marketing site**.

### 1.1 Key Supersedures

This document **replaces** the visual-direction document wherever conflicts exist:

| Aspect | Visual Direction | Evidence UI Addendum |
|--------|------------------|----------------------|
| Primary audience | Marketing / prospect | Authenticated pilot user |
| Hero section | Full-screen marketing hero | **NOT APPLICABLE** |
| Navigation | Marketing navigation | **Authenticated workspace only** |
| Entry point | Landing page withCTA | **Logged-in dashboard** |
| Data representation | Aspirational | **Evidence-first, status-transparent** |

### 1.2 Evidence-First Principle

The frontend must make evidence states **immediately visible and scannable**.

Per AGENTS.md sections 5, 6, 8, 14, 32 and 42:

- **UNKNOWN** — data not yet available
- **INCONCLUSIVE** — evidence insufficient for conclusion
- **OBSERVED** — raw observation from provider
- **INFERRED** — derived from observations with reasoning
- **MODELLED** — generated by model with parameters
- **CONFIRMED** — manual verification completed
- **SOURCE_UNAVAILABLE** — provider offline or unreachable
- **CONFLICTING** — providers disagree

**Never** hide evidence states behind hover or interaction.

**Never** present INFERRED/MODELLED data without explicit labeling.

## 3. Provenance and Freshness Display

### 3.1 Mandatory Metadata Fields

For every observation, model output, or derived product, display:

```text
Provider: <provider name>
Observed: <ISO 8601 timestamp>
Ingested: <ISO 8601 timestamp>
Freshness: <stale / current label>
```

### 3.2 Freshness Logic

| Condition | Label | Color |
|-----------|-------|-------|
| `now - observed_at < 1h` | "Atual" | `#15803d` |
| `now - observed_at < 24h` | "Recente" | `#854d0e` |
| `now - observed_at < 7d` | "Desatualizado" | `#b45309` |
| `now - observed_at >= 7d` | "Obsoleto" | `#991b1b` |
| `provider unavailable` | "Fonte indisponível" | `#991b1b` |

### 3.3 Implementation Pattern

```tsx
<dl className="provenance-metadata">
  <dt>Fonte</dt><dd>{providerName}</dd>
  <dt>Observado</dt><dd>{formatTimestamp(observed_at)}</dd>
  <dt>Importado</dt><dd>{formatTimestamp(ingested_at)}</dd>
  <dt>Atualidade</dt><dd className={`freshness-${freshnessStatus}`}>{freshnessLabel}</dd>
</dl>
```

## 4. Demonstration vs. Production Data

### 4.1 Labeling Requirement

**All demonstration/synthetic/test data must be visually distinct** from production data.

### 4.2 Implementation

```tsx
<span className="badge badge-demo">
  Dados de demonstração
</span>
```

**Styling:**
```css
.badge-demo {
  background: #f3f4f6;
  color: #374151;
  border: 1px dashed #d1d5db;
}
```

### 4.3 Scenarios Requiring Labeling

- Test fixtures
- Mock API responses
- Sample datasets
- Prototype features
- Placeholder content

**Never** display unmarked demonstration data in production UI.
